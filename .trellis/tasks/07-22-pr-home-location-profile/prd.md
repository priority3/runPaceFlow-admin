# PRD:常跑地点迁出配置面板

## 背景

常跑地点(PR_HOME_LAT/LNG/LABEL)本质是**用户画像数据**("我平时在哪跑步"),不是服务配置。它以三个 env 形状的键存在于配置面板,是历史架构惯性(settings 是当时唯一现成的取值通道):

- 手填经纬度的体验差(用户要自己去地图上查坐标);
- 语义归属错位:PR 的画像数据散落在 friend_profile 之外;
- 2026-07-22 配置瘦身时它们刚被「幽灵键转正」进面板——趁生产库还**零数据**(无人填过),把形状纠正掉,避免生根。

## 目标

1. 常跑地点落 friend_profile(PR 画像的正确归宿),配置面板三键移除;
2. PR 伙伴面板提供地点查看/编辑(显式设置、清除回退自动推导);
3. 天气/环境感知链路行为不变:显式值优先,未设置时活动起点聚类推导,评测 fixture 通道不受影响。

## 范围

**做**:friend_profile 新列 + 读写 API + PrPanel 编辑卡片 + `getHomeLocation()` 改读 profile + settings 三键摘除(注册表与读取代码)。
**不做(后续可选)**:地图选点控件(admin 无地图栈,MVP 用输入框+推导预览);聊天内让 PR 自己改地点的写工具(涉及写操作边界,和 l4 写边界评测联动,单独立项)。

## 验收标准

1. PR 伙伴面板可查看当前生效地点及来源(显式设置 / 按常跑路线推导 / 未知),可保存显式地点(lat/lng 校验合法范围)、可清除回退推导;
2. 保存后天气 provider 下一次构建上下文即用新地点(TTL 缓存内允许 ≤10 分钟延迟或主动失效);
3. `PR_HOME_LAT/LNG/LABEL` 从 SETTING_DEFINITIONS 与全部消费代码移除,配置面板 38→35 键;
4. 评测 fixture 优先级不变,eval 全链路不受影响;
5. lint + tsc 通过;部署后无 schema 迁移事故(runtime ALTER 幂等)。
